# 页面搭建器项目文档

更新时间：2026-09-16。首个可运行增量已完成并安装为本地开发版；完整首版仍在推进。最新实施情况始终看 PROGRESS。

文档随代码一起维护。目标是让下一次任务能直接继续开发，也让用户能核对实际完成了什么。

| 文档 | 回答的问题 | 更新时机 |
|---|---|---|
| [功能方案](FEATURE_PLAN.md) | 做什么，首版边界在哪里 | 用户需求或范围变化 |
| [开发与审核流程](DEVELOPMENT_WORKFLOW.md) | 如何开发、检查、评审和交付；采用哪些笔记方法 | 工作方法经实践需要调整 |
| [架构与关键决策](ARCHITECTURE.md) | 如何分模块；哪些约束必须保持；为什么这样选 | 接口或设计取舍变化 |
| [验收表](ACCEPTANCE.md) | 凭什么认定功能可用 | 实现、验证或修复某一项 |
| [进度与证据](PROGRESS.md) | 当前状态、实际失败、下一步和成果位置 | 每个可运行增量及任务交接 |
| [基线交接](BASELINE_HANDOFF.md) | 初始代码与组件库在哪里，有哪些已知缺口 | 初始事实需纠正时；不作为实时进度 |

读取顺序：新任务先读项目 AGENTS → 本页 → PROGRESS；实施前对照 FEATURE_PLAN、ARCHITECTURE、ACCEPTANCE。详细工程方法按需查 DEVELOPMENT_WORKFLOW。

每个功能使用验收编号串联需求、改动与证据。每条事实只在对应文档维护，其他文件链接过去。代码与说明冲突时查证并修正，不能简单认定任何一方永远正确。

已读取的 Obsidian 工程笔记及采用方式列于 DEVELOPMENT_WORKFLOW。原始知识库未修改；本项目是这些方法的实践和沉淀位置。
