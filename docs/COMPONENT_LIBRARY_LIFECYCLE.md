# 组件库独立更新与插件解耦

更新：2026-09-17。9 月 16 日[核查](COMPONENT_LIBRARY_DECOUPLING_AUDIT.md)记录的是修复前状态；本轮已修复静态属性、变体伴随状态、固定资源清单、原生脚本替换和资源消息过大等问题。已验证当前 5 个组件的 37 种公开变体，未将其扩称为整个 51 个生产组件接入。远程仓库和自动发布不在本期范围。

## 修复前缺口

当前构建脚本将插件内的 `vendor/b2b` 复制进 `dist/ui`；页面创建写死 `componentLibraryVersion: "b2b-3.4.7"`；组件属性目录在 `src/catalog.ts` 手工维护。修改原组件库不会自动进入已安装插件，现有版本尚不满足独立更新要求。不能把重新复制资源、重新构建并安装整个插件称为“组件库单独更新”。

## 职责与独立版本

| 部分 | 负责内容 | 更新边界 |
|---|---|---|
| 组件库 | 组件外观、交互、公开属性与运行资源 | 独立源码、版本与发布内容 |
| 搭建器 | 拖拽、布局、属性面板、页面历史、AI 交互和导出 | 不维护第二份组件实现 |
| 适配层 | 将真实组件协议映射成可编辑能力、合法转换与兼容检查 | 允许保留编辑器专用规则；必须对照实际组件协议验证 |

组件库版本、适配协议版本、插件构建版本、页面格式版本和页面 revision 各有含义，不混用。组件库没有可靠发布版本时使用可追溯的内容摘要识别快照，不能虚构版本号，也不能用插件版本代替。

## 首版实施默认值

1. 支持配置独立组件库来源，先满足现有本地 `ai-design-system` 的工作方式；记录来源但不写死用户桌面路径。远程仓库、在线商店和自动发布不是这次新增要求。
2. 提供可发现的“检查组件库更新 / 应用组件库版本”操作。已安装插件读取独立运行资源或版本缓存；兼容的组件库更新不要求修改搭建器源码、重新构建或重新安装整个插件。服务重载或页面刷新如有需要需明确说明，不伪称热更新。
3. 更新先进入候选快照：读取真实描述与资源清单，检查协议、依赖和已开放组件的代表性渲染；通过后再原子切换可用版本。失败保留当前可用版本，显示原因；保留可回退版本。
4. 页面绑定明确的组件库身份与不可变版本/内容摘要。新页面可使用已验证的新版本，已有页面继续使用原版本；升级已有页面需检查兼容性并保留回退依据，不能随库目录变化静默改变页面。
5. 原组件协议是事实来源，组件目录尽可能由真实 manifest/describe/schema 读取或生成。编辑器允许的属性子集、显示名称及复杂转换可在适配层维护，但应校验其确实存在、组合合法，不能把手写完整枚举当另一套组件协议。
6. 新发现的组件或变体只代表“库中存在”；尚未完成编辑适配的能力应显示未适配或不开放，不能自动宣布51个组件全部可编辑。
7. 导出依据页面绑定版本打包完整运行资源、版本信息与资源摘要；之后组件库升级不影响该导出，离开插件仍能按说明运行。不依赖可变 latest 地址或原机器绝对路径。
8. 旧插件内快照可以作为首次迁移或离线默认来源，但后续更新不能依赖改写插件缓存。兼容性破坏涉及适配协议时，明确需要升级适配层，不能承诺所有未来库版本永远免改插件。

具体配置位置、版本缓存结构、升级入口和锁文件字段由开发任务选择最小可行实现，补充到架构与使用说明。修改组件库本体前遵循其 AGENTS.md 及相应验证要求；先复用现有发布/描述能力。

## 可验证的完成条件

| 编号 | 必须证明的行为 |
|---|---|
| L01 | 插件安装产物和版本不变，仅更新独立组件库；执行更新流程后，新页面确实使用新的已验证组件资源 |
| L02 | 现有页面保持原绑定版本，组件外观与数据不被静默改变；主动升级可检查差异并有明确失败/回退处理 |
| L03 | 不兼容协议、缺失资源、错误变体或校验失败不会替换当前可用版本；错误可见且原页面仍能打开 |
| L04 | 插件 UI、AI 组件查询与后端校验使用一致的实际组件版本和能力，不能只更新外观而保留旧协议 |
| L05 | 更新和回退后可复核组件库版本/摘要；刷新或重启不会丢失选定的来源与页面绑定 |
| L06 | 升级组件库后，之前导出的工程在独立目录仍可运行；其自身页面描述重新导入时明确解析原版本，缺失时清楚提示 |

测试使用隔离组件库副本制造两个可追溯版本，不为验收随意修改用户生产组件库。结果必须记录实际加载版本与插件构建标识，不能只证明文件复制成功。

## 首版实现

- `src/library.ts` 从内置离线基线建立内容摘要快照，目录名为 `b2b-<digest16>`；manifest 记录完整 SHA-256、真实 sourceVersion（可为空）、adapterVersion、来源、别名和文件闭包。
- `component_library_check` 只创建并验证候选；`component_library_apply` 只切换新页面默认版本；`page_upgrade_component_library` 显式升级一个页面并携带 expectedRevision。重新 apply 旧 snapshotId 即回退新页面默认版本。
- 验证同时读取 `api-schema.js`，检查五个页面组件适配字段和八个编辑器控件必要字段，并用 Chrome 实际 render/validate 页面组件与编辑器控件。缺文件、协议破坏或 Renderer 失败不会改 settings。
- 页面持久化 `componentLibrary` 绑定，HTTP 与 UI 按该 snapshotId 提供 Loader；页面切换到不同快照时整页重载，避免两个全局 runtime 混合。导出从页面快照复制资源。
- 独立来源通过工具/API 的 `sourcePath` 配置；只在 apply 后写入隔离缓存 settings，不写死 `/Users/...`。环境变量 `PAGE_BUILDER_LIBRARY_DIR` 可把快照根目录指向测试或运维目录。

## 验证结论

`tests/library.test.ts` 使用两个临时源码状态验证 L01–L06：兼容 Token 变化产生新摘要时插件构建摘要不变，新旧页面分别钉住不同快照；旧页面导出和重新导入仍解析旧快照；篡改 C-02 公开协议时候选被拒绝且当前版本不变；旧 snapshotId 可回退；缺失快照明确返回错误。测试不修改 `ai-design-system` 源目录。

## 2026-09-17 当前使用方式与实现

左侧「组件库来源与更新」填写独立的 `design-source` 路径，点击「刷新并重载组件」。服务读取源文件，创建不可变快照，先在严格无网络的原生资源环境验证组件，再验证当前页面全部节点，通过后升级当前页并设置新页默认版本。刷新的是当前页引用的样式、运行实现和公开协议，页面节点、文案与排列不变；升级记录支持撤销。

组件库更新完全手动：不设置定时检查、不监听源目录、不开启自动更新。用户点击按钮时才检查源库并重新载入；存在未应用的属性草稿或正在保存时提示先完成编辑。即使源库没有变化，按钮也重载当前组件。校验失败不更新页面；如果服务端已保存新版本而前端资源加载失败，保留原画面、暂停编辑并提示重试，不能误报为服务端未更新。兼容更新不需要重新构建或安装插件；破坏性 API 变更仍可能需要升级适配层。其他页面和旧导出继续固定原快照。升级初始化时移除旧版本的自动刷新配置。

原生面板是动态注入的文档，没有可重新请求的页面 URL。组件重载不调用 `location.reload()`，也不关闭 MCP App 连接/选区发布权：先完整取得候选资源，再销毁旧组件实例并释放库创建的脚本、样式、字体和全局导出，在当前文档重建组件。编辑器状态、pageId 和宿主连接保留；旧异步控件通过运行代数失效。资源读取失败保留当前运行库，替换中途失败尝试恢复上一可用库；重试使用服务端已保存的 revision，避免永久版本冲突。HTTP 浏览器入口仍可使用普通页面重载。

库运行期还拥有 document/window 上的事件监听：source.bindInteractions(document) 采用全局委托，单个实例 destroy 不会移除这些监听。输送层在释放运行库时统一移除，防止刷新后一次点击被处理多次。插件自身的 App 桥接和 pagehide 监听在输送层安装前注册，保留到真正关闭面板。

- `library-schema.ts` 从页面快照的公开 schema/presets 读取属性、枚举、默认值和非业务的变体伴随状态；不再使用静态枚举限制 C-23。`catalog.ts` 仅提供当前 5 个编辑适配入口、显示文案和基础字段顺序；它的旧协议仅供没有库上下文的领域单测回退，线上 PageStore 必须注入 LibraryManager。
- `RendererValidator` 复用真实组件库做写入前校验，UI、MCP 查询、后端都使用页面绑定版本。复杂变体合法转换仍属于适配层；未来新增需要结构变换的变体可能需要补转换规则。
- 资源文件按运行目录及支持的资源扩展名发现，不受内置基线文件列表限制。摘要与快照写入使用同一份读取字节，避免摘要/内容不一致；相同候选并发安全；settings 使用跨进程锁。
- `library-transport.js` 只负责脚本、样式、CSS import、字体资源输送，库 JS 原字节执行。删除了依赖源代码格式的字符串替换。实际完整库资源约 19.9 MB；MCP 资源按 100 万字符分段读取，避免 SDK 10 MiB 消息上限。
- UI 基础属性外增加「全部组件属性」，按当前库公开 schema 建表；对象/数组支持组合提交。源库不提供嵌套字段描述时表单只能依据已有结构，不承诺任意未知的嵌套配置已完成易用性设计。非法组合不入库。
- 老页面缺精确绑定时，先钉住原先解析的快照，保持 revision/内容/历史；默认库更新不再改变旧别名解析。导出剔除本机 sourcePath，资源仍来自页面快照。

证据：`tests/native-resource.test.mjs` 支持 `PAGE_BUILDER_TEST_SOURCE` 指向真实源库，覆盖 37 种变体与 4 种标签类型、全属性修改、保存重开及严格无 HTTP 资源加载；`tests/library-refresh.test.mjs` 实际改变源 CSS、新增 CSS 依赖、改变公开说明、只调整 Loader 空格，验证无自动源库请求、多次手动刷新、失败保留、草稿保护和插件构建不变。`tests/library.test.ts` 验证固定版本/回退/导入导出；浏览器流程另覆盖真实拖拽、内容编辑、移动、删除、撤销、预览与独立导出。真实 Codex 宿主加载本次安装仍单独验收。

## 2026-09-18 属性栏来源与解耦边界

属性栏不是运行时由 AI 分析组件 DOM。`readLibraryCatalog` 读取页面快照的 `api-schema.js` 与 `presets.js`；前端再读取同一运行库的 `describeComponent().api.props`，按类型生成文本、数字、布尔、枚举和对象/数组表单。

| 内容 | 当前权威 | 手动刷新后的变化 |
|---|---|---|
| 组件渲染、样式、公开字段、类型、默认值、枚举 | 独立组件库的页面快照 | 校验通过后更新；已有页面文案与配置不会被新默认值覆盖 |
| 「全部组件属性」中的字段集合 | 当前公开 schema | 新字段自动出现，移除字段不再列出；破坏性删除会先受兼容校验约束 |
| 常用字段顺序、显示条件和复杂变体数据转换 | 插件适配层 | 仍需要插件修改，不能称完全解耦 |
| 属性中文标题、英文枚举的中文显示 | 插件显示词典 | 已知值有中文；未知值保留源标识，不筛掉新选项；源库尚无统一编辑器本地化协议 |

核查用户页面 revision 169 / `b2b-7a13fb7f6e235b6b`：五个组件的 76 个公开属性与当前独立源库逐项相同；变体数量为按钮 5、输入 6、选择器 9、卡片 10、标签 7。源库展示页有额外的组合维度：例如 C-42 的 interaction/feedback/surface 会转换为 checkable/checked/closable/loading/disabled/bordered/solid，它们不是同名公开 props；avatar 属于 type。卡片网格示例还提供多条演示数据，而搭建器转换保留用户内容，只创建最小可编辑结构，因此“同一个变体”不意味着与展示例图内容相同。

本次补齐现有枚举的中文显示，底层值仍为源 API 标识。C-23 的公开选中事件返回 label，所以显示层用当前选项表反向解析原始值，保留数字类型并处理中文重名，禁止把译文写入页面 schema。常用栏与全部属性使用相同映射；源字段/枚举集合不由词典决定。测试在隔离源库新增 reviewNote 字段并收窄 appearance 枚举，手动刷新后表单同步变化，插件构建摘要不变。

后续若要让编辑器布局、中文文案和复杂条件也随组件库独立更新，需要在组件库中正式设计并维护编辑元数据协议，包括字段顺序/分组、显示名称、选项名称、条件和变体迁移。本次没有伪称已实现该协议，也没有解析或复制 specimen 的展示页面逻辑。

## 2026-09-18 编辑元数据 v1 落地（取代上节对应未完成项）

`components/runtime/builder-contract.json` 已由组件库任务提供，插件按 BUILDER_PROTOCOL.md 消费。五组件 76 个公开字段的中文名、分组、顺序、控件与条件从源协议读取；元数据与实现共同参与快照摘要。只改源协议再点击手动刷新，属性栏随之改变；元数据缺失的新字段仍出现，旧节点 props 不重置。错误 JSON、版本或越界字段/选项拒绝候选，原页与默认快照不切换。

仍未完全迁出插件的是复杂内容转换（输入组合、选择器富选项、卡片子项/页签、头像文字补齐）。简单互斥状态优先读取源 transitions；复杂适配器作为明确的后备而保留。布局容器设置始终由插件管理，不混进组件 props。内置 vendor 保留离线旧协议基线，没有复制独立源的编辑元数据；使用新协议需指向组件库并手动刷新。
