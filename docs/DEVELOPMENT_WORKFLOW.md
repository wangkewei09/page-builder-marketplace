## 4. 测试策略

对页面操作、版本冲突、撤销重做、持久化、导出等高影响逻辑，先明确可观察行为和边界，再写必要测试。重构有可用行为时先建立保护测试。不要用与实现同构的断言、只测 mock 的用例或任意覆盖率数字替代验收。

重点覆盖：

1. 多个同类组件具有不同节点标识、内容和位置。
2. 合法容器移动保持树结构；禁止循环嵌套、非法插槽和丢失子节点。
3. 文字、变体、尺寸和状态严格遵循真实 describe().api.props；非法组合不写入。
4. 批量操作全成功或全不提交；错误不会留下半张页面。
5. 过期版本更新不会覆盖用户新编辑；任务/页面标识不会串页。
6. 删除与撤销恢复正确的子树和排列；重做一致；输入框中的删除键不删节点。
7. 关闭、重启、重新打开后内容和结构保持一致，保存失败有明确反馈。
8. 导出资源闭包完整，独立目录运行不依赖桌面绝对路径；重新导入自身页面描述一致。
9. Renderer 更新和销毁后没有重复事件、遗留 DOM 或资源错误。

先跑覆盖本次改动的最小充分检查集；共享页面协议、保存机制或公共渲染变化应扩大回归范围。禁止通过删除失败断言、弱化约束或隐藏异常来换取通过。

## 5. 代码审核方式

实现完成后单独进入评审阶段，重新以需求和失败路径检查，不把“写出来了”当成“已验收”。有独立评审者时以独立复现为准；未运行独立评审则如实标注，不把自审包装成独立评审。不因参考笔记提到多 Agent 就自行增加子代理或切换模型。

重点看实际接口两端是否匹配、操作是否可回滚、生命周期是否完整、异步结果是否过期、导出是否包含真实依赖、每个抽象是否有实际消费者。特别检查：

- Page Schema 是唯一持久化页面来源，UI、AI 和导出不各自保存不同事实。
- 用户内容作为数据处理；文本和属性不成为可执行脚本或未转义 HTML。
- 本地资源服务不能通过路径穿越读取任意文件；导入和导出限制路径与输入大小。
- 组件渲染与编辑器选择/拖拽交互职责明确，原组件事件不会重复绑定。
- 异常、重试、重复操作、并发和不兼容变体都有可解释处理。
- 无关重构、镜像状态、仅为假设需求增加的复杂度应删除或说明必要性。

问题格式：严重程度、触发条件、实际后果、文件位置、复现或测试证据、修复后复测结果。阻断交付的功能错误、数据丢失、越权读取和工程无法运行等问题必须先修复；只报有证据的问题，避免大量不影响结果的格式意见。

## 6. UI 与宿主验收

使用真实组件 Renderer；截图和测试服务器必须来自交付代码。验证桌面和窄屏下的选中、拖拽落点、文字编辑、变体切换、保存恢复和导出。至少留一段完整交互录屏或等效的连续可复核交互证据；静态截图不足以证明拖拽成功。

单独区分以下完成状态：

- 本地浏览器能运行。
- 插件包格式和资源检查通过。
- 当前 Codex 实际加载了新插件。
- 原生右侧入口点击后显示正确编辑器。
- AI 实际读取并修改了对应页面。

一项通过不代表其他项通过。不能以元数据声明、mock-host 测试或“打开请求已排队”冒充真实宿主可用。必要时可验证浏览器备用入口，但需明确记录它与原生入口的区别。

插件更新还需检查已经打开的任务：MCP server key 应作为稳定标识，资源 URI 变更需处理旧引用；不能只有新任务可启动而没有旧任务的恢复说明。若用户入口消失，优先查宿主注册/资源日志并恢复入口，暂停无关改动和重复打包。

必要检查通过后即推进可用版本交付；仅在新增修改、失败或未解决的具体风险出现时补测对应范围。全量测试次数不是进展指标，也不能替代当前用户环境的直接故障排查。

## 8. 方法如何应用到当前开发

开发采用短循环：选择一个可验收的用户行为 → 核对协议和失败边界 → 写必要的行为验证 → 实现最小完整路径 → 检查差异和真实操作 → 记录证据与决策 → 进入下一增量。第一个增量优先跑通“真实按钮加入页面、改文案、保存、重开”，随后扩展首批组件与布局，不先堆满面板再处理数据一致性。

按变化原因拆模块：组件能力变化集中到适配层，编辑体验变化集中到编辑器，存储方式变化集中到存储层。共享页面规则只维护一处；不因为后续可能有复杂需求就预建微服务、插件框架或大量开关。

用版本化文档串联意图、规格、实现和证据：FEATURE_PLAN → ARCHITECTURE / ACCEPTANCE → 代码与测试 → PROGRESS 中的评审和交付结果。项目 AGENTS 只保留必要入口与不变量；不要求每次任务重读所有 Obsidian 文章。

稳定重复的检查落入项目脚本和测试，例如页面校验、构建、导出资源检查；确有 CI 时记录其结果，否则只称本地检查。暂不为了形式安装额外治理框架、全局 Hooks 或自动监控。通用 Skill 在流程经过实际使用后再提炼，不预先把未经验证的方法包装成标准。

缺陷处理形成下一轮输入：最小复现 → 查明原因 → 修复 → 回归测试 → 必要的规则修订。复测仍失败则继续修复；不能靠增加提示词数量或“下次注意”结束问题。

首个增量验证出的两条工程规则：一是快速连续 UI 操作必须串行提交，异步 Renderer 重建必须带 generation 并销毁过期实例；只依赖服务端 revision 不能避免旧画面叠加。二是宿主 UI 与接入组件库的 CSS 自定义属性必须使用不同命名空间，并在真实组件加载后检查计算样式；静态截图前的样式看起来正常不能替代联调。

## 独立组件库更新验证补充

原生重载验证必须模拟真实文档交付方式：动态注入的 widget 不是可导航 URL，也不等同于 iframe.srcdoc。`native-refresh.test.mjs` 在空 iframe 中注入真实 MCP HTML，实际点击刷新并断言文档、宿主连接、选区、页面内容保留；连续源样式/代码更新、无变化刷新、读资源失败和替换失败恢复均需覆盖。HTTP 刷新通过与 srcdoc 首屏通过不能证明这条原生交互可用。

同时验证源码、传输与消费者：对真实源库只读测试；在隔离副本改变可见 CSS、添加依赖、改变公开元数据并保留插件构建摘要。候选必须走与宿主相同的无网络资源通道，覆盖消息大小边界。不要以 append 注释或 schema 相等代替真实画面变化。所有集成测试显式隔离 pages、library cache 和 exports，避免测试初始化写入真实库设置。安装前备份持久化数据；源码通过、安装成功和当前宿主已加载分别记录。

## 两个项目协作编辑协议

先落一份共同线路契约并明确各自写入目录，再启动另一项目任务。发现真实 API 不能表达的能力先对齐字段与语义；本次 controlWhen 来自数字空值的实际联调，禁止两端各自扩展不同格式。源库不修改样式/Renderer，消费者不复制一份源元数据；有源协议时使用源描述，无文件时才回退。

同时检查 raw schema 与运行时有效 schema（当前 presets 会改变默认值），显式清空不要误用 reset。验证应覆盖“源元数据改动、插件构建不变、UI 更新、旧内容保留”，以及错误候选原子拒绝。截图等待完整启动/控件重建完成，不能只等到画布出现。测试报告区分预期注入的拒绝请求和非预期控制台错误，不静默过滤后者。


## 拖拽交互回归补充

使用真实鼠标 dragstart/dragenter/dragover/drop/dragend，分别验证松手前的落点/让位和松手后的页面结构，预览不应增加 revision。覆盖源节点移走后的索引、占位改变命中元素后的快速松手、静止指针、取消/原位放回、嵌套/换行布局、外部写入冲突及保存失败。长页面需检查画布背景覆盖完整内容、浏览器原生滚动和自定义滚动是否冲突、取消后是否停止。静态证据等动画结束再截图，同时用交互轨迹或实际动画状态证明动画确实发生，不能仅凭截图宣称拖动成功。


## 插件重装后的宿主检查

2026-09-21 实测：官方 CLI 安装新版会清理旧版本目录，但已运行的宿主插件进程和新任务入口仍可能复用旧进程。交付前调用宿主实际 page_builder_open 比对 build.pluginVersion；不能以磁盘版本、CLI 安装成功或新任务代替。若 resource/read 报旧目录 ENOENT，当前恢复方式是用户完整退出 Codex（⌘Q）再启动；不擅自结束用户其他任务，也不手工回填安装缓存。只有验证了正式的宿主热重载路径后，才可以承诺插件更新无需重启。组件库的手动重载与此分开。

## 局部渲染与上下文引用验收

“没有整页刷新”应验证 DOM/Renderer 身份和内部输入状态，不仅观察截图或是否发生导航。对新增/复制统计实际挂载，对移动断言无重建，对删除断言仅释放目标；延迟新组件准备、注入渲染失败、淘汰旧异步结果和 runtime reset 时检查旧画面保留与资源释放。快速“保存中换选→添加”应验证最终父容器，不能依赖固定等待掩盖写入竞争。

上下文测试按真实附件语义覆盖：普通选中不附加、显式加入、换选保持目标、目标更新/删除、跨面板显式接管、失败/超时重试、teardown 清空。默认选区和用户显式引用可以不同，AI 操作说明必须与 UI 一致。Foundation 验收改源变量观察外壳响应，组件仍与直接 Renderer 的原生输出比较；禁止覆盖内部 CSS。

多选需使用相同 componentId、不同 nodeId/props 的实例验证身份，分别检查部分删除与全部删除，并在同步失败后换选再重试。持久活动节点不能冒充完整引用组。macOS 原生 Ctrl-click 被系统作为右键；本机用真实 ⌘ 点击验收，再用 Ctrl 事件验证 Windows 分支，并如实注明未做 Windows 实机验收。

## 已验证的方法：编辑位置迁移（2026-09-22）

把输入从属性栏移至画布时，回归应继续验证同一保存结果、错误草稿、引用身份和版本冲突，并把测试动作改成新的用户入口；不能保留隐藏的旧输入框来凑通过。明确源组件控件自己的长度限制。等待控件挂载完成且获得焦点后再输入，特别是 Playwright fill 不检查 inert。复杂设置以真实属性路径去重；协议文件与 Renderer 一起按快照验收。

## 原位编辑必须验证原位（2026-09-22）

原先浮层输入虽能保存公开属性，仍不符合“组件里直接改”。验收需检查光标焦点属于原组件文字/原生输入框，没有额外弹窗；编辑前后的字体、颜色、文字边界与图标身份一致；输入后原位置显示草稿、取消恢复原节点与属性。操作语义、保存正确与视觉体验三者分别验证，不能用前两者代替最后一项。

## 项目范围切换的实施补充（2026-09-24）

引入项目/工作区时，先把身份传递覆盖 UI、HTTP、MCP、截图和 AI 附件，再增加入口。用两个含相同逻辑 ID 的本地检出来验证隔离；不能只测两个不同 ID 的项目。创建跨文件内容时先准备依赖、最后发布清单，或直接从事实目录派生成员，避免维护会半写的重复列表。组件快照可移植性必须在空缓存且非内置版本下验证。项目切换还需验证未提交草稿、晚到轮询、旧上下文和不同库版本的运行时重载。

### 项目卡片增量：交互完成与组件上限

工作台操作期间 `data-ready=false` 表示仍在处理，不代表视图已经关闭。浏览器用稳定根节点验证离开，以 ready 验证可操作；计数断言前等待此次动作完成。路径断言统一比较 realpath，但创建或移动目标不存在时不能提前 realpath。组合属性要遵循源 Renderer 已声明上限（例如 C-21 长文本固定 240），不能从普通输入参数推测；挂载失败必须让流程显式失败，不能留下半张可保存表单。

## 原生系统窗口的验收边界（2026-09-24）

长时间等待用户的本地窗口采用启动/状态/取消三步，界面与 OS 适配器分开验证。隔离浏览器可注入选择/取消/失败来验证真实业务持久化，但不能据此声称系统窗口已显示或返回正确。OS 层要另有真实点击证据；工具不能观察时明确保留待验收，安装文件一致也不能证明已运行宿主热更新成功。
